# 词典结果

这个目录是 DeepDict 的成品。

| 文件 | 内容 |
| --- | --- |
| `DeepDict.dictionary.zip` | macOS 词典包，用于系统自带的"词典"应用和查询弹窗 |
| `DeepDict.mdx` | MDict 格式，用于欧路词典、GoldenDict、MDict 等 |
| `DeepDict.stardict.zip` | StarDict 格式，用于 GoldenDict、KOReader 等 |
| `entries.jsonl.gz` | 全部 298,458 条词条记录，一行一个 JSON，包括被排除的词 |
| `included-words.csv` | 最终收录的 259,269 个词 |
| `corrections.jsonl` | 生成后又经过修正的 12 条词条 |
| `accuracy.csv` | 准确性抽查的逐词结果，800 个词 |

三种词典包的内容相同，都是收录的 259,269 个词。安装方法见仓库根目录的 README。

MDict 和 StarDict 两个包生成后做过回读校验：用打包库自带的读取器和另一个独立的读取库各读一遍，词条数和内容都与源数据一致。但它们还没有在欧路词典、GoldenDict、KOReader 这些应用里逐一实测过显示效果。

## 数字

| 项目 | 数量 |
| --- | --- |
| 候选词 | 298,458 |
| 收录 | 259,269 |
| 　其中只标类别的专有名词 | 116,621 |
| 排除 | 39,189 |
| 义项 | 345,747，平均每词 1.33 个 |
| 带解释的义项 | 239,321，占 69% |

排除的原因：缩写 19,075 个，不是英语词 6,983 个，含义不确定 6,000 个，拼写错误或碎片 5,894 个，不规范的缩约拼写 609 个，其余 628 个。

带解释的义项比例不高，是因为专有名词多数只标一个类别，没有解释。

## 收录规则

是否收录、怎么释义，由生成词条的模型按 `deepdict/prompts/entry-generation-system.md` 判断。其中三条规则决定了词典的面貌：

- **专有名词只标类别。** 释义是"人名""地名""机构名""品牌名""作品名""角色名"之一，不给音译。重名很常见，所以不把一个名字当成某个确定的对象；有广为人知的所指时，解释以"可指……"开头，说明这只是所指之一。
- **缩写只留常见的。** 一般读者会反复遇到、而且意思基本唯一的才收，如 usa、dna、gdp。冷门的、各行业意思不同的、各种代码一律不收。
- **敏感词照常释义。** 脏话、蔑称不回避也不加评论，用"粗俗""蔑称"等标签注明语体。

## 词条格式

`entries.jsonl.gz` 解压后每行是一条记录，按词头排序。下面是一条记录展开后的样子：

```json
{
  "word": "orangutan",
  "include": true,
  "suitability_score": 9,
  "meaning_confidence": 10,
  "exclude_reason": null,
  "senses": [
    {"pos": "n.", "context_label": "", "gloss_zh": "红毛猩猩"}
  ],
  "meta": {
    "model": "gpt-6.2-astra",
    "effort": "high",
    "prompt": "3039c7a9",
    "generated": "2026-11-28"
  }
}
```

| 字段 | 含义 |
| --- | --- |
| `include` | 是否收录。为 `false` 时 `senses` 为空，`exclude_reason` 说明原因 |
| `senses` | 义项，按阅读中遇到的频率排序 |
| `pos` | 词性，如 `n.`、`v.`、`adj.` |
| `context_label` | 语境或领域标签，可为空 |
| `gloss_zh` | 简短的中文对应词 |
| `definition_zh` | 一句话解释，可以没有 |
| `suitability_score`、`meaning_confidence` | 模型自评的 0–10 分，只用于质量检查时排序 |
| `meta` | 这条记录是怎么来的，见下面"来源记录" |

格式的权威定义是 `deepdict/schema.py` 里的 `validate_entry()`。

### 来源记录

每条记录的 `meta` 说明它由什么生成、何时生成，方便以后按模型或提示词版本筛出一批词条来更新。

| 字段 | 含义 |
| --- | --- |
| `model` | 生成这条记录的模型 |
| `effort` | 推理强度。只有通过 Codex 生成的才有 |
| `prompt` | 提示词版本，取提示词文件内容哈希的前 8 位 |
| `generated` | 生成日期 |
| `edited`、`edited_by` | 事后修正过的词条才有：修正日期和修正者 |

现有记录的来源：

| 模型 | 推理强度 | 提示词 | 时间 | 条数 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `gpt-6.2-astra` | high | `3039c7a9` | 2026-11 | 297,471 | 2026 年 11 月扩充时生成，包括对原有词条的重新生成 |
| `gpt-5.5` | low | `f1d4eda8` | 2026-06 | 987 | 重新生成时被新模型改判为排除、但保留了原词条的词 |

其中 12 条在生成后又经过修正，带 `edited` 标记，同时列在 `corrections.jsonl` 里。

`gpt-5.5` 那 987 条的来源是事后补记的：2026 年 6 月的运行没有记录模型名，`gpt-5.5` 是根据同一天的 Codex 日志推定的，日期也只精确到月。其余记录由生成程序在写入时自动记录，模型名和日期都是确切的，日期按 UTC 计。

提示词版本对照：

| 哈希 | 对应的提示词 |
| --- | --- |
| `9322ee5b` | V1 提示词，在 git 历史的 `prompts/entry-generation-system.md` |
| `f1d4eda8` | V2 提示词，在 git 历史的 `deepdict/prompts/entry-generation-system.md` |

## 词条是怎么来的

- **V1（2026 年 4 月）** 用 DeepSeek 生成了 `wordlists/merged.csv` 的 100,683 个词，收录 91,813 个。
- **V2（2026 年 6 月）** 把这 91,813 个词用新的提示词全部重新生成，走的是 Codex 订阅。新提示词把"解释"从可选项变成了主体。另外生成了 `wordlists/cogsci/words.csv` 的 6,196 个学术词。V2 共 106,879 条记录，收录 96,669 条。
- **扩充（2026 年 11 月）** 用 `gpt-6.2-astra` 分四部分生成，全部走 Codex 订阅：

| 部分 | 词数 | 收录 |
| --- | --- | --- |
| V2 排除的词重新判断，加上 ECDICT 带标注的词和缩约形式 | 11,692 | 7,103 |
| wordfreq 其余全部纯字母词 | 187,276 | 155,094 |
| V2 收录的词重新生成 | 96,669 | 94,433 |
| 近几年的新词，候选由几个大模型分领域列出 | 2,821 | 2,639 |

V2 收录的 96,669 个词重新生成后，按下面的规则合并：

| 情况 | 条数 | 处理 |
| --- | --- | --- |
| 新词条仍然收录 | 93,446 | 采用新词条 |
| 新模型改判为排除，原因不是缩写 | 879 | 保留 V2 词条 |
| 新模型判为缩写，但词频高且 V2 词条只有一个义项 | 106 | 保留 V2 词条 |
| 新模型判为缩写的其余词 | 2,236 | 排除 |
| V2 里修正过、新词条不如修正版的 | 2 | 保留修正版 |

合并前从释义有变化的词条里抽了 300 条做盲评：把新旧两个版本匿名交给 Claude Opus，让它判断哪个对读者更有用。新版更好 156 条，旧版更好 29 条，持平 115 条；旧版有 6 条错误，新版有 1 条。

新词那一部分的候选怎么来的，见 `wordlists/README.md`。这些词大多比生成模型的训练数据新不了多少，所以多做了一步核对：随机取 60 条，让模型联网搜索后重新生成，再与不联网的版本对比，60 条的含义全部一致。模型以"含义不确定"排除的 6 个词，以及抽查中被质疑的 3 个词，是联网后生成的。

## 质量

词条是 LLM 生成的，不应当作权威词典数据使用。

### 准确性抽查

从收录的词条里分层抽了 800 条，逐条对照参照词典判定。抽查是在加入近几年的新词之前做的，当时词典有 256,630 条；之后加入的 2,639 条新词单独抽查过，见下面"扩充过程中的检查"。

**抽样。** 按风险层和词频分成 15 层，每层至少抽 20 条（不足 20 条的层全抽），其余名额按各层的词条数分配。所有比例都按各层在词典里的比重加权，置信区间用层内自助法（bootstrap）估计。风险层来自不消耗 token 的规则扫描，见 `deepdict/README.md`。

**参照。** 剑桥英汉双解词典、剑桥英语词典、《美国传统词典》。800 条里有 366 条至少在其中一部查得到。参照词典的原文只用于比对，不在本仓库里。

**判定。** 由 Claude Opus 按 `deepdict/prompts/accuracy-judge.md` 的标准逐条判定，判定时不知道词条属于哪个风险层。被标出的词条由 Claude 全部复核，另外抽读了 60 条判为正确的普通词条，没有发现漏判。整个过程没有人工逐条核验。

**结果。**

| 判定 | 占比 | 95% 置信区间 | 样本中的条数 |
| --- | --- | --- | --- |
| 正确 | 99.2% | 98.6% – 99.8% | 791 |
| 有瑕疵 | 0.6% | 0.2% – 1.2% | 7 |
| 有错误 | 未发现 | | 0 |
| 无法核对 | 0.1% | 0% – 0.4% | 2 |

按参照词典是否收录：

| | 占词典 | 正确 | 有瑕疵 | 有错误 | 无法核对 |
| --- | --- | --- | --- | --- | --- |
| 参照词典收录 | 40% | 99.1% | 0.9% | 未发现 | 无 |
| 参照词典未收录 | 60% | 99.3% | 0.4% | 未发现 | 0.2% |

按词频：

| 词频 | 占词典 | 正确 | 有瑕疵 | 有错误 |
| --- | --- | --- | --- | --- |
| 高频（每百万词出现 10 次以上） | 3% | 97.2% | 2.8% | 未发现 |
| 中频（每百万词 1 到 10 次） | 8% | 99.9% | 0.1% | 未发现 |
| 低频（每千万词 1 到 10 次） | 22% | 99.6% | 0.4% | 未发现 |
| 极低频（每千万词不到 1 次） | 67% | 99.1% | 0.7% | 未发现 |

**读这些数字时要注意的：**

- **"未发现"不等于没有。** 800 条里没有发现错误，只能说明错误率很低；按样本量推算，大概率低于 0.5%，也就是整部词典里仍可能有上千条有错误的词条。
- **样本里 44% 是只标类别的专有名词。** 这类词条只有"人名""地名"这样一个类别，几乎没有可以判错的内容，所以"正确"的含金量低于普通词条。
- **参照词典未收录的那 60%**，判定依据只有模型自身的知识，证据比有参照的部分弱。
- **漏收义项不计为瑕疵。** 本词典有意只收常见义项，判定标准里写明了这一点。扩充前那次抽查（96.0% 正确）的判定标准更严，把"漏了最常见的义项"算作瑕疵，所以两次的数字不能直接比较。
- **保留下来的 V2 词条质量偏弱。** 样本里有 12 条是重新生成时保留的 V2 词条，其中 3 条有瑕疵；其余 788 条里只有 4 条。这类词条在词典里共 987 条。
- 抽查标出的 7 条有瑕疵的词条已经修正，记录在 `corrections.jsonl`。上面的数字是修正前测得的。

逐词结果在 `accuracy.csv`，其中 `judge_verdict` 列是判定者的原始结论，`verdict` 列是最终采用的结论，这次两者相同。

### 扩充过程中的检查

- **生成异常。** 生成程序会把模型拒答和无法解析的输出单独记下来。四部分共 298,458 个词，拒答和无法解析的都是 0。
- **分段抽查。** 新增的词各自在合并前抽查过：第一段 200 条，第二段 300 条，新词 300 条，都没有发现错误。新词那 300 条里只有 12 条在参照词典里查得到，其余全凭判定模型自身的知识。
- **新旧盲评。** 重新生成的 V2 词条在合并前做过 300 条的新旧盲评，见上面"词条是怎么来的"。

### V2 阶段的检查

V2 的 106,879 条记录做过规则扫描和双模型审查：风险最高的 A 层 647 条由 DeepSeek 和 GPT 先后审查，两者都判有问题的 66 条由 Claude 逐条复核，改了 19 条。之后的准确性抽查又修正了 34 条。这些词条绝大多数已在扩充时被重新生成的版本取代。
